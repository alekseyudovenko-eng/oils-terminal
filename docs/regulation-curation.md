# Регуляторика маркировки «без пальмового масла»: как обновлять

Раздел «Регуляторная политика» в закрытой лаборатории (`/lab/regulation`) строится из одного файла —
`data/regulation.json`. Из него же собираются две Excel-таблицы для скачивания:
`public/lab/regulation.xlsx` (русская) и `public/lab/regulation-en.xlsx` (английская).
Этот документ — инструкция для еженедельного обновления (вручную или запланированной задачей).

## Охват

20 стран: Польша (PL), Чехия (CZ), Словакия (SK), Венгрия (HU), Румыния (RO), Болгария (BG), Эстония (EE),
Латвия (LV), Литва (LT), Хорватия (HR), Беларусь (BY), Молдова (MD), Украина (UA), Россия (RU), Казахстан (KZ),
Кыргызстан (KG), Таджикистан (TJ), Туркменистан (TM), Узбекистан (UZ), Армения (AM).
Плюс общие нормы ЕС (`scope: "EU"`) и ЕАЭС (`scope: "EAEU"`): они относятся ко всем странам блока.

Что считается относящимся к теме:
- обязательное указание вида масла/жира в составе, запрет «растительного жира» без расшифровки;
- правила добровольных заявок («без пальмового масла», «palm oil free», «bez oleju palmowego» и т. п.), борьба с вводящими в заблуждение заявками;
- запреты и ограничения пальмового масла в продуктах (детское, школьное питание, молочная продукция);
- молочная продукция с заменителем молочного жира: наименования, маркировка, отдельные полки, предупреждения;
- импортный контроль масел и жиров, лабораторный контроль, пошлины и акцизы на пальмовое масло;
- цифровая маркировка и прослеживаемость (Честный знак, национальные системы), если касается масложировой продукции;
- стандарты (ГОСТ, СТ РК, O'z DSt и т. п.) на масла, спреды, маргарины;
- устойчивость: EUDR и её отсрочки/упрощения, требования к происхождению масла.

Не относится: общие нормы безопасности пищевых продуктов без связи с маслами и жирами; новости рынка (они идут в ленту новостей).

## Формат `data/regulation.json`

```json
{
  "updatedAt": "2026-10-26",            // дата последней проверки (YYYY-MM-DD), ставится при каждом обновлении
  "period": { "ru": "…", "en": "…" },   // охват по времени, меняется редко
  "countries": [ … 20 записей … ],
  "measures":  [ … нормы … ]
}
```

Страна:

| поле | что это |
|---|---|
| `code` | код ISO из списка выше, не меняется |
| `bloc` | `EU`, `EAEU` или `other` |
| `name` | название на ru/en/uz/kk/ms, не меняется |
| `claimPhrase` | как заявка звучит на упаковке на местном языке (например, `bez oleju palmowego`); пустая строка, если не встречается |
| `claimUse` | насколько распространена заявка: `high`, `medium`, `low`, `none`, `nodata` |
| `practice` | ru/en, ≤400 символов: кто и на каких продуктах использует заявку (сети, бренды, категории) |
| `summary` | ru/en, ≤400 символов: коротко о национальных нормах по теме |

Норма (`measures[]`):

| поле | что это |
|---|---|
| `id` | уникальный латинский slug: `<страна или блок>-<суть>`, например `kz-mark`, `eu-eudr` |
| `scope` | `EU`, `EAEU` или код страны |
| `type` | `disclosure`, `claims`, `ban`, `dairy`, `import`, `traceability`, `tax`, `standard`, `sustainability` |
| `status` | `in_force` (действует), `upcoming` (принято, вступает позже), `proposal` (проект/предложение) |
| `date` | дата вступления в силу (для проекта — дата внесения/публикации): `YYYY-MM-DD`, `YYYY-MM`, `YYYY` или `""` |
| `act` | ru/en, ≤160: точное название акта с номером и датой |
| `title` | ru/en, ≤120: суть нормы одной строкой |
| `text` | ru/en, ≤600: что именно требуется, для каких продуктов, с какого числа |
| `url` | прямая ссылка на официальный текст (EUR-Lex, eaeunion.org, adilet.zan.kz, lex.uz, pravo.gov.ru, sozd.duma.gov.ru, zakon.rada.gov.ua, legis.md, pravo.by, arlis.am, cbd.minjust.gov.kg и т. п.); вторичный источник — только если официального текста нет в открытом доступе |

На сайте нормы с датой с 2024 года, кроме проектов, попадают на шкалу «календарь вступления в силу».

## Еженедельная проверка

1. **Статусы по датам.** Для каждой нормы `upcoming`, у которой `date` уже наступила, проверьте по официальному
   источнику, что она действительно вступила в силу (не перенесена), и переведите в `in_force`.
2. **Проекты (`proposal`).** Для каждого проекта проверьте, что с ним произошло: принят (→ `upcoming` или
   `in_force`, новая `date`, новый `act` с номером принятого акта), отклонён/отозван (удалите норму и упомяните это
   в отчёте), без движения (ничего не меняйте).
3. **Переносы и изменения.** Отдельно проверьте нормы с переменчивыми сроками: EUDR (`eu-eudr`, `eu-eudr-deriv`),
   изменения ТР ТС 022 (`eaeu-022-amend`), законопроекты Госдумы (`ru-duma`, `ru-warning`), цифровая маркировка
   (`ru-cz`, `kz-mark`, `uz-mark`), Украина (`ua-3947*`), Узбекистан (`uz-*`).
4. **Новые нормы.** Поиск за последние 7–10 дней по каждой стране и по блокам ЕС/ЕАЭС, на английском и местном
   языке (польский, чешский, словацкий, венгерский, румынский, болгарский, эстонский, латышский, литовский,
   хорватский, русский, украинский, казахский, узбекский, кыргызский, таджикский, армянский). Примеры запросов:
   «пальмовое масло маркировка закон», «заменитель молочного жира маркировка», «olej palmowy etykietowanie
   przepisy», «palm oil labelling regulation <country>», «ТР ЕАЭС масложировая продукция изменения».
5. **Практика маркировки.** Если найдено новое и проверяемое (сеть убрала пальмовое масло из СТМ, крупный бренд
   стал ставить заявку, регулятор оштрафовал за заявку), обновите `practice` и при необходимости `claimUse` страны.
6. **Правила достоверности.** Каждое изменение — только по открытому и прочитанному источнику; дата и номер — со
   страницы самого документа, не из сниппета поисковика. Ничего не придумывать: если не удалось проверить —
   не вносить, а упомянуть в отчёте как «требует проверки». Тексты — нейтральные, без оценок.
7. Поставьте `updatedAt` = дата проверки (даже если изменений нет: на сайте это «данные на …»).

## Сборка и проверка

```bash
node scripts/validate-regulation.mjs                      # исправить все ошибки
pip install openpyxl --break-system-packages              # если нет
python3 scripts/regulation/build_xlsx.py                  # → public/lab/regulation.xlsx
python3 scripts/regulation/build_xlsx.py --lang=en        # → public/lab/regulation-en.xlsx
# пересчёт формул (если доступен скрипт навыка xlsx):
python3 /mnt/skills/public/xlsx/scripts/recalc.py public/lab/regulation.xlsx 60
python3 /mnt/skills/public/xlsx/scripts/recalc.py public/lab/regulation-en.xlsx 60
```

Если recalc недоступен, файлы всё равно корректны: Excel пересчитает формулы при открытии.

Коммит — только `data/regulation.json` и два xlsx, сообщение `regulation: YYYY-MM-DD (+N новых, ~M изменено, −K)`.
Vercel пересобирает сайт после пуша в `main`.
